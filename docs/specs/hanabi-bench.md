# Hanabi Bench

Build a local experiment system independent of the deployed website. Reuse the game's rule definitions and verify headless gameplay against the production engine.

## Decisions

- A headless CLI supports manual play and machine-readable interaction, all five existing rule sets, and two through five seats. Initial experiments use three-player base Hanabi, fixed seating, and immediate termination when a critical card is discarded or misplayed. Existing saved runs retain their stored rules.
- Hands have fixed ordinal order, oldest on the left and newest on the right. Each draw is appended at the highest ordinal; surviving cards keep their relative order. Players cannot rearrange cards. Observations contain no spatial layouts or coordinates.
- Players receive the visible board and intervening public events, including clue matches, revealed plays/discards, and visible draws. Own cards and the undealt deck remain hidden. Supply no inferred identities, strategy hints, or other players' private logs.
- Rules are complete, fixed, and separate from conventions. The starter conventions are immediate-play clues and oldest-unclued default discards. Rules-only runs are supported.
- Each seat has its own provider/model/effort/options and private conversation. Initial real runs use local authenticated Codex, GPT 6.1 Sol, high effort; Opus and API-key integrations are outside this implementation. Executable discovery checks the terminal PATH and the macOS ChatGPT app bundle; `HANABI_CODEX_PATH` selects an explicit executable. A deterministic scripted provider supports offline verification, not model-quality claims.
- Every move includes a private explanation without an imposed brevity requirement. Every acting player receives a post-action reflection opportunity, including terminal actions. Logs are standard behavior.
- The benchmark runs fixed configurations on matched seeded deals. Report perfect-game rate first, average score second, execution failures, latency, and available usage. Fresh conversations for every game; conventions do not evolve within benchmark runs.
- The hill climber plays one fresh deal, lets the Dreamer inspect the complete transcript, private logs, and prior experiment history, then immediately uses its revision in the next game. No adoption-test batch or cooldown. The Dreamer can rewrite the entire freeform convention document or choose no change, and must explain its decision separately. Rules cannot be edited.
- One convention lineage and fixed player configuration per hill-climb run. Preserve immutable convention versions, parent links, explanations, games, and failed attempts. Players have no cross-game memory. Optional post-game player discussion is configurable and off initially; independent debriefs happen before sharing hidden information.
- The intended first trial is fifty games, then stop. Restart is manual and can continue the same lineage. Build verification uses only small smoke runs, never the fifty-game trial. Iteration results are observations, not proof that each revision improved performance.

## Implementation checkpoints

- ✅ Headless engine, privacy boundary, complete rule text, and differential gameplay tests. Differential checks cover 120 full games across every variant, seat count, and early-ending setting.
- ✅ Local Codex adapter, strict configuration, single-game orchestration, private explanations/reflections, and durable run artifacts. Authenticated tool-free Codex inference and offline integration tests pass.
- ✅ CLI manual/JSON play, fixed-configuration evaluation, versioned hill climbing, and manual continuation. Subprocess tests exercise each command, replay, validation, and failure reporting.
- ✅ Automated checks and an authenticated local-Codex end-to-end run. One three-player Sol/high game scored 24/25 in 62 turns, replayed exactly, and produced convention version 1 with a separate explanation. No fifty-iteration trial was run. Independent review findings are resolved.
- ✅ Fixed hands and executable shortcut. Draws append rightmost, surviving cards retain order, and observations contain no spatial layout. Rearrangement requests and movement-enabled configurations are rejected. The original transcript replays exactly. All 998 tests pass with one environment-dependent skip; lint, typecheck, and formatting pass. The `hanabi-bench climb --games=1` launcher completed an offline scripted game and Dreamer review; CLI subprocess tests exercise the launcher.

- ✅ Local read-only experiment viewer: `review PATH` opens saved games, hill climbs, and evaluations; `run`/`climb --watch` follows live artifacts and remains open until Ctrl+C. The existing board shows each selected move's decision and reflection, with conventions and Dreamer explanations. Chrome verification covers the recorded 24/25 model game, late reflections, live move updates, and paused scrubbing. A scripted watched climb ends immediately on critical loss and completes its Dreamer review. Full-suite tests, focused artifact/HTTP/cancellation tests, lint, typecheck, and both frontend builds pass. Access is loopback-only and token-protected; linked artifacts cannot escape the selected directory. Production review remains finished-game-only by default.
- ✅ Review layout reserves separate space for navigation beneath a scrolling content area. Expanded conventions and explanations cannot overlap the scrubber. Chrome checks confirm identical navigation coordinates across all 60 replay positions and usable layouts at 800px and 390px widths; 15 focused review tests, lint, typecheck, and formatting pass.
